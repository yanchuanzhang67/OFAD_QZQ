## 1. 结论与测试基线

New_ORAD 当前处于“核心算法原型 + 单元测试验证”阶段，尚未达到系统级 SDD 完整交付状态。Phase 1～4 的主要算法骨架已存在，但训练数据闭环、严格接口契约、ROS 2 集成和真实仿真验证不完整；Phase 5 已有闭环脚本、ONNX 入口和 TensorRT API 设计，但真实 CARLA/Gazebo、域随机化 harness 和端侧实现尚未完成。

```text
python -m pytest -v
69 collected, 63 passed, 6 skipped, 16 warnings
```

该结果与旧文档的 `64 passed, 5 skipped` 不一致。跳过项正是专家日志、危险边界、CARLA/Gazebo 闭环和完整 ROS 2 节点测试，故单测通过不能等价为系统完成。

| Phase | 成熟度估计 | 判断 |
|---|---:|---|
| Phase 1 | 约 75% | 类型、几何、运动学核心存在；契约校验和 C++ 对等实现不足 |
| Phase 2 | 约 60% | 多模态 BEV 存在；Occupancy 和统一输入契约未闭合 |
| Phase 3 | 约 45% | 网络/loss API 存在；训练、数据和实证指标缺失 |
| Phase 4 | 约 55% | 确定性安全投影和控制器存在；NMPC、ROS 2 实跑缺失 |
| Phase 5 | 约 30% | 部署框架存在；真实闭环与端侧实现未完成 |

## 2. 架构契约

Python import 层未发现循环引用，主依赖基本单向：

```text
utils → perception / safety / sim / orad_ros2
perception + policy + safety + sim → deployment / scripts
```

| 项目 | 审计结果 |
|---|---|
| 公共类型 | 集中在 `utils/types.py`，未重复定义，是正确基础 |
| `SensorPacket` | 只有定义，没有实际生产者/消费者 |
| `BEVFeature` | `occupancy` 已声明，但感知始终不填充 |
| `VehicleState` | 数组反序列化无严格长度、版本、单位、frame 和有限值校验 |
| `OccupancyGrid` | origin yaw 被忽略；负边界用 `int()` 向零截断，可能错误落入第 0 格 |
| World Model | `src/world_model` 为空；实际 RSSM/WorldModel 嵌入 `policy`，与 SDD 分层不符 |
| 配置 | `configs/` 为空；BEV、车辆极限、dt 等在多个模块重复 |
| ROS 2 | 轨迹为裸 `Float32MultiArray`，缺 header、frame、时间戳和 shape 契约 |
| C++ | TensorRT 只有头文件；SafetyFilter 没有 C++ 对等实现 |

几何转换分别存在于 `utils.transforms`、`perception.bev_fusion` 和 `sim.carla_closed_loop`。当前虽大体遵循 `H=y、W=x`，但没有共享 `GridSpec/FrameId/Transform`，存在持续漂移风险。

## 4. P0 风险

1. **CARLA IMU 维度错误**：回调保存 accel+gyro，但 `tick()` 只返回 accel `(T,3)`；模型契约为 `(T,6)`，真实运行会在 GRU 处失败。
2. **Occupancy/trajectory frame 错配**：局部 LiDAR 构建的 occupancy 被 world-frame 安全轨迹查询，碰撞过滤位置不可信。
3. **空轨迹不主动制动**：SafetyFilter 可返回空轨迹，控制器随即输出零油门、零刹车，车辆可能继续滑行。
4. **多相机未同步**：所有相机写入同一 deque，不能保证相机身份和仿真 frame 一致；`timeout` 参数未使用。
5. **无效模型可静默评估**：缺 checkpoint 可用随机策略，不存在路径不报错，`strict=False` 允许不完整权重。

## 5. 其他技术债

- `SafetyFilter.optimize_casadi()` 仍为 TODO，不是 NMPC 实现。
- `collision_threshold` 未使用；reward 网格外视为自由，SafetyFilter 则视为占用。
- 感知缺 camera 数、标定数、shape、batch、dtype、NaN/Inf 校验。
- 点云超长直接保留前 N 点，可能丢失近场危险点。
- 部署 forward 中 RSSM 后验随机采样，同一输入可能输出不同轨迹。
- ONNX 有 16 条导出警告，且无 Runtime 数值回归。
- `configs/`、`launch/` 为空，与原项目说明不一致。
- integration/closed-loop 测试仍是显式 skip 骨架。
