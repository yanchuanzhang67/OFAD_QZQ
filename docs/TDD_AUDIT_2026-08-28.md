## 2. 核心类单测诊断

### 2.1 BEVFusion

已有：输出 shape/dtype、batch>1 CPU、条件 CUDA、IMU 姿态旋转、非对称 BEV shape 和精确落点。

缺失：

- 空点云、单点、全零、全部越界点云。
- `P<num_points` pad 与 `P>num_points` truncate。
- NaN/Inf、错误点通道、错误 camera 数和图像尺寸。
- IMU `(B,T,3)`、错误 T、错误 batch/device。
- 标定数量/shape/focal length 校验。
- pad 零点不产生伪特征。
- `BEVFeature.occupancy` 非空的 SDD Red 测试。
- frustum `P_total` 与静态 scatter index 一致性。

### 2.2 HybridPolicy

已有：forward、BC backward、imagination shape、world-model backward、actor/critic gradient、RSSM sequence shape。

缺失：

- `eval()` 同一输入重复推理确定性。
- BEV/IMU shape、batch、NaN/Inf 的明确失败行为。
- horizon≤0、空 sequence、terminal continue 边界。
- lambda-return 与手工公式一致性。
- KL 极值数值稳定性。
- actor 输出 finite、速度非负和 heading/轨迹物理范围。
- freeze world model 后 actor update 不改变其参数。
- checkpoint config 匹配和保存/加载输出一致性。

99% 覆盖说明代码几乎都被执行，不等于训练或控制语义充分正确。

### 2.3 SafetyFilter

已有：转向截断、运动学可行、碰撞截断、安全轨迹保持、曲率估计、违规诊断、极大曲率投影、侧向加速度封顶、空轨迹和 policy arc。

缺失：

- 首 waypoint 碰撞后的主动停车语义。
- 网格边界、网格外、inflation 跨格和 `origin.yaw`。
- dt≤0、wheelbase≤0、max lateral acceleration≤0。
- NaN/Inf、负速度、倒车、时间戳不单调。
- jerk 和 steering-rate 的精确逐步断言。
- `use_casadi=True` 的真实行为。
- 输出 finite、输入不被原地修改和 frame mismatch 检测。

### 2.4 PurePursuitController

已有：直线、转弯、转角截断、侧向加速度封顶、空轨迹、短轨迹和动态 lookahead。

缺失：

- 零速度启动、目标与车辆重合、目标位于车后。
- 极高速度与 12 m lookahead 上界、负目标速度。
- NaN/Inf、yaw 跨越 ±π、乱序轨迹和倒车。
- 空轨迹必须产生最大制动，而非仅 speed/steering 为零。
- 控制连续性、转角速率和 jerk。
- ROS message 长度、header/frame 和 Gazebo stamped message。

现有 `test_controller_empty_trajectory_stops` 没有断言负加速度或 brake，不能证明车辆实际停车。

## 3. 其他测试盲区

### 公共类型

`VehicleState`、`Trajectory`、`OccupancyGrid`、`BEVFeature` 和 `SensorPacket` 没有专用测试。应补 round-trip、严格数组长度、二维 grid、正 resolution、负边界、origin yaw、inflation、camera/IMU/timestamp 同步等契约。

### OffRoadReward

应补 N=0/1/2、occupancy/attitude shape 错配、dt=0、网格外安全语义、collision threshold、H/W 不一致、NaN/Inf 和 frame mismatch。

### ONNX

当前只断言文件存在且非空。应将 `onnx.checker` 变成硬断言，并增加输入输出名称/shape、batch 1/2 ORT 推理、PyTorch↔ORT 误差、模型状态副作用、checkpoint 失败路径、确定性输出和 TensorRT build 冒烟。

## 4. Skip 与 Fake/Mock 策略

### 可转为纯 CPU Green

| 能力 | 建议 Fake/测试 |
|---|---|
| ROS 2 节点 | 分离 adapter 与控制核心；FakeNode/FakePublisher/FakeMessage 测 topic、parse、publish、timer |
| CARLA runner 编排 | FakeVehicle/FakeSensorStack/spy callable 测调用顺序、终止和异常回退 |
| CARLA packet | Fake event + frame-indexed queue 测 camera 身份、同步、IMU 6D 和 timeout |
| Safety 危险边界 | 参数化合成 OccupancyGrid 测边缘、inflation、首点碰撞和网格外 |
| 开环 contract | 小型真实网络或 deterministic fake 测 SensorPacket→BEV→policy→safety |
| 闭环指标 | 合成 EpisodeMetrics/FakeRunner 测门槛和 CLI 退出码 |

### 不应被 Mock 替代

- 专家日志 ADE<0.3 m：Fake 只能测 ADE 计算器，最终必须使用真实数据和训练权重。
- 危险边界 100% 拦截：合成回归之外仍需代表性 hazard dataset。
- CARLA 20° 坡和 Gazebo 悬挂：必须由真实仿真物理验收。
- TensorRT 精度/时延：必须在目标 CUDA/TensorRT/硬件环境验收。

推荐双层测试：

```text
CPU Contract Tests：每次提交执行，不允许 skip
Environment Acceptance：CARLA/Gazebo/ROS2/TensorRT 专用 CI
```

## 5. TDD 规范与质量门槛

仓库快照只能证明当前测试状态，不能证明历史上的“测试先行”。严格 Red–Green–Refactor 应保存失败测试、最小实现、绿色回归和重构后的 CI 证据。

建议门槛：

```text
全项目 branch coverage：当前基线不得低于 79%，逐步提升到 85%
核心 safety branch coverage：≥95%
新增/修改代码 coverage：≥95%
P0 fail-safe 分支：100%
CPU integration contract tests：不得 skip
```

覆盖率门槛不能替代物理约束断言和场景矩阵。

## 6. 首批 Red Stage 顺序

1. `sim`：CARLA IMU 输出必须为 `(T,6)`。
2. `sim/safety`：局部 occupancy 与 world trajectory 必须转换或明确拒绝。
3. `controller`：空安全轨迹必须产生最大制动。
4. `perception`：空点云、pad、truncate、错误 IMU shape。
5. `policy`：eval 同输入重复推理必须确定性一致。
6. `types`：负边界、origin yaw、非法 resolution。
7. `deployment`：PyTorch 与 ONNX Runtime 数值一致性。
8. CPU fake closed-loop：完整 tick 编排与异常回退。

在选定具体模块后，先提交对应失败 pytest（Red），确认失败原因与需求一致，再进行最小实现（Green）和无行为变化重构。
